# D2 / hlhb 외부 엔진 실제 실행 결과

**4회 실행 중 DEV2025 2회 유효, SEEN2026 2회 실패·소비. 두 기간 비교는 미완료이며 체크포인트로 종료한다. 재시도 여유는 0이다.** 2026 실패는 이번 벤치마크 연결 코드의 달력·캐시 인덱스 오류이며, 전략 성과나 Freqtrade 자체 결함으로 판정하지 않는다. 사후 수선은 합성자료에서만 확인했고 시장자료로 재실행하지 않았다.

DEV 최초 차이는 **BCH-USDT, origin 452, 2025-03-07 20:00 UTC 청산**, 원형 395.74 → FT 395.71이다. 시간청산 41건 중 29건(일반 17·runner 12)의 가격이 달랐으며 나머지 12건은 종가와 다음 시가가 같았다. 이 차이로 순손익 합계가 **−3.193014614625 trade-bps** 변했다. FT 청산 가격을 사후에 원형 종가로 덮어쓰지 않았다. 따라서 이번 결과는 청산가격까지의 완전 동일성 PASS가 아니다.

## FT 자체 손익과 선물 검증의 한계

| DEV2025 FT 자체 산출 | D2 | hlhb |
|---|---:|---:|
| 거래별 1,000 USDT 명목, FT 비용 후 손익 합계 | +1,862.88169886 USDT | −46.57808313 USDT |
| 개별 거래 수익률의 단순 합계 | +1.86195072349 | −0.04655480574 |

마지막 행은 계좌 누적 수익률이 아니다. FT 자체 산출은 편도 수수료 0.0005만 반영하며, 연구비용 표의 스프레드·시장충격·펀딩 대용값과 별개다. 공통 표는 D2와 동일한 동결 비용 해시 및 최소 왕복 20bps 규약을 적용한다. 실제 동시점 체결·수수료 등급·체결 지연·서명 있는 실측 펀딩 경로는 확보되지 않았다. 누락 비용을 0으로 간주하지 않는다.

입력 가격은 원래 **BingX USDT perpetual 4h** 그대로다. 다른 거래소 가격으로 대체하지 않았다. 실행기는 네트워크를 차단한 FT의 **spot 가격 매칭 경로**에 합성 선형 메타데이터(1배·종목별 1,000 USDT·7슬롯·넉넉한 지갑·tick 1e-12)를 전달한다. 따라서 이는 오프라인 가격경로 비교이며 **BingX 선물 live 지원·계약 크기·증거금·청산 검증이 아니다**. 설치본 FT 코어 매칭·청산·수익 계산 파일은 수정하지 않았다.

4h OHLC만 있으므로 봉 안의 실제 가격 순서·체결시각은 모른다. limit/SL/ROI/trailing은 FT의 봉내 가정에 따른다. hlhb 82건의 청산시각에 봉내 불확실성이 있어 보유시간·펀딩비용 범위를 기록했다. 시간 비용만 달리한 순손익 범위 **−1,832.85~−1,819.21bps**는 여전히 적자다. 강제 종료는 실현 승리로 세지 않고 미완결 평가로 분리한다. 유효한 DEV 두 결과에는 미완결이 없고, 실패한 SEEN 결과의 강제 종료 수익은 성과로 사용하지 않는다.

## 원형과 실제 resolved config

- Freqtrade **2026.7**, source `52bc96f4480b1a0da6a9b455bd00b17fbb6786a5`, Python 3.12.13. 공식 wheel SHA256 `be08e26ed0f642ce9ada8b7fcfb1ed6766dc8ef95f131650c1d3fecf419f3815`. 실제 의존성은 environment/pip-freeze.txt와 requirements-hashed.txt에 고정했다. 설치된 client 패키지 버전과 엔진 버전을 혼동하지 않는다.
- 공식 source의 backtesting·trade_model·strategy interface·resolver 4개 파일을 설치본과 byte 비교했다. 설치 RECORD 10,690개 파일을 확인했다. 초기 pyarrow 손상 파일의 SIGBUS는 공식 pinned requirements 재설치로 복구한 후 실행했다. 정확한 기록은 environment/에 있다.

- hlhb: 4h, startup 30, SL **−32.11%**, ROI **0분 62.25% / 703분 21.87% / 2849분 3.63% / 5520분 0%**. trailing enabled, positive **1.17%**, offset **1.86%**, offset 도달 후에만 적용. 진입·청산 limit, SL market, 거래소 SL false. `ignore_roi_if_entry_signal=true`, `exit_profit_only=false`.

## 자료 연결, 실행 예약, 실패 경계

canonical ref는 `6d6335d1c9ad7ecb1e9597da85c2eb87635561e1`. 첨부 체크포인트의 53개 manifest 해시를 확인하고, 기존 DEV/SEEN prefix loader가 회수한 packet·lineage를 원래 D2 SPEC의 가격·비용·정책 해시와 일치시켰다. DEV는 종목당 2,250봉, SEEN은 3,748봉(준비 3,028·평가 720)이다. SEEN은 과거 이미 노출된 자료이며 독립 OOS가 아니다. 과거 OOS 이름의 파티션이 이 준비 구간에 포함된 노출 이력도 보존했다. 신규 시세 수집·미사용 OOS 접근·유료 AI·실주문·배포는 모두 0이다.

동일 목적 확인은 master `bd2ca5348367e71238641814043d9795b62fa512`에서 한 번 수행했다. 기존 PR1219는 FT2026.8/BreakV2/Heracles의 별도 실제 실행 69~72를 보유한 미병합 작업이었다. 그 48후보/72평가 원장을 그대로 승계하고 재실행하지 않았다. 이번 scope의 누적 원장은 **49후보/76평가**다. 다른 작업의 canonical 원장과 PR1219 브랜치를 덮어쓰지 않고 scope BUDGET에 승계 사본과 추가4회를 저장했다.

SEEN D2는 FT가 앞 3,027행을 제거한 엔진 커서를 전체 prefix 캐시에 적용해 stale 완료봉을 읽었다. 최초 진입 시각 검사가 거절됐고 뒤이어 custom_exit 오류 3,443회가 발생했다. `D2_CALLBACK_ERRORS_OR_ENTRY_ACCOUNTING`으로 종료했다. SEEN hlhb는 전체 prefix를 엔진에 넘긴 달력 연결 오류로 원시 거래 34건 모두 평가 시작 전 진입이었고 `ENTRY_OUTSIDE_APPROVED_PERIOD`로 종료했다. 두 실패를 삭제하거나 거래를 사후 필터링하여 성공으로 바꾸지 않았다.

`analysis/engine_view_fix.py`는 full-prefix 지표 계산 후 엔진/캐시 뷰만 정렬하는 별도 수선이다. 실제 FT 엔진의 합성 360봉·중간 평가 시작 시험에서 D2 6건과 hlhb 4건의 기간·callback 연결을 확인했다. **UNEXECUTED_ON_MARKET_DATA**이며 이번 실패를 소급해 해소하지 않는다. 원래 동결 코드와 경제 산출물은 그대로 보존한다.

마감 CI는 저장 결과 해시·정산·산술만 검증하며 가격 다운로드, Freqtrade 설치, 경제 실행을 호출하지 않는다. `CLOSURE.json`의 잔여 실행은 `[]`, FULL 잔여는 0이다. 이어서 실행하려면 이 두 실패와 별도 수선 상태를 승계해야 하며, 이번 상한으로 재실행할 수 없다.
