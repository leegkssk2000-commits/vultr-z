4. 반복 실패의 원인을 먼저 닫는다

아래 질문에 증거로 답한다.
- 조사한 donor가 실제 호출된 실행 경로에 들어갔는가, 아니면 parent만 실행했는가?
- 과거에 구현된 donor의 중요한 조건이 후속 재구축에서 누락됐는가? 처음부터 없었는가? 의도적 별도 변형인가?
- source ID와 전략 이름만 연결하고 규칙별 대응을 생략했는가?
- 자체 손절/만료/재진입/시간봉 선택을 원문의 규칙으로 잘못 표시했는가?
- 테스트가 자체 명세의 실행만 검사하고 원자료와의 대응은 검사하지 않았는가?
- 서로 다른 대조군·봉·체결·기간의 차이를 과최적화 또는 전략 실패 하나로 설명했는가?
- 독립 전략 실패만으로 문맥·청산 재료의 가치까지 부정했는가?

설명만 쓰지 말고 해당 경로를 테스트/검수/표시 규칙으로 막는다. 기존 해시 보호·CI를 재사용하고 큰 범용 프레임워크를 새로 만들지 않는다.

5. 원문 → 역할 → 명세 → 구현 → 사례의 대응 검수

인터넷의 공개 원저자 자료·공식 기술문서·원논문·원저자 사례를 직접 읽는다. 검색 요약·AI 요약만으로 완료하지 않는다.
기존에 읽은 유효한 자료와 코드를 회수해 중복 조사를 줄인다. 유료자료 무단 접근, 비공개 거래내역 추정, 성공 홍보문구의 검증 수익률 취급은 금지한다.

규칙별로 다음을 연결한다:
source URL/저자/문서 버전·위치 → 실제 규칙 → 원래 시장·시간범위 → 맡길 역할 → 기계적 명세 → 함수/코드 SHA → 실행 호출 경로 → 검증 사례·테스트 ID.
조건은 반드시 '원문 직접 규칙 / 시장·TF 이식 가설 / 자체 설계 선택 / 미확인'으로 구분한다.

핵심 사항:
- 배경 문맥, setup 형성, trigger, 무효화, 재진입, 청산, 보유시간, 비용·체결을 함께 검토한다.
- 원문이 정성적이면 자의적 숫자를 원문이라고 표시하지 않는다. 시험 가능한 해석은 사전 고정한 별도 adaptation으로 진행할 수 있다.
- 원자료의 완전한 비공개 운용법이 없다는 이유로 유용한 공개 부품의 연구를 전부 막지는 않는다.
- 동시에, 확인 불가능한 핵심을 만들어 '정확 재현'이라고 주장하지 않는다.
- 원자료에서 확인되는 진입/비진입/정상 눌림/실패 사례를 코드보다 먼저 기대 행동으로 정한다. 차트가 읽히지 않으면 가격·시각을 창작하지 않는다.
- 인공 fixture는 논리시험용임을 표시한다. 실제 원저자 거래 재현 또는 경제표본으로 계산하지 않는다.
- 핵심 조건을 제거하거나 시간순서를 뒤집은 변형에서 검사가 실패하는지 확인한다. mutation이 살아남으면 검수 공백을 기록한다.
- 원문 검수 역할은 구현 코드를 따라 정답을 만들지 않는다. 가능한 경우 구현 담당과 별도 reviewer/subagent가 원문·명세·사례를 직접 읽고 반증한다. 별도 사람이 검토한 것처럼 말하지 않는다.
- 사례 일치성은 수익성 PASS가 아니며, 과거 손익을 보고 해석을 골라서는 안 된다.

가벼운 규칙표와 최소 테스트로 먼저 한 후보의 끝까지 연결을 입증한다. 나머지 후보의 원자료 감사는 그동안 병렬 진행한다.

'대표 정의와 다르다'만으로 버그 판정하지 않는다. 당시 의도한 규칙과 실제 구현이 다른지, 아니면 의도한 변형의 경제성이 나쁜지를 구분한다.

7. 결과 분류·재시험 허용 기준

각 항목을 증거에 따라 나눈다. 분류는 감사 보고용이며 runtime SSOT enum을 몰래 바꾸지 않는다.
- 원자료 대응 확인, 경제실험도 비교 가능: 기존 경제 판정 유지.
- 핵심 조건 누락/순서 오류/미이식: 확인된 차이만 수선한 새 후보 허용.
- 의도한 adaptation: 원문 재현 실패로 부르지 않고 그 변형의 유효성만 평가.
- data/execution/sample 부족: 경제적 최종 탈락으로 확대하지 않음.
- standalone만 평가하고 재료 역할 미검증: 역할별 연구 대상을 분리.
- 출처·구현·비용이 맞는데도 실패: 실패 유지, 동일 재실행 금지.

기존 모든 FAIL 원장과 비용은 보존한다. 잘못 시험한 구현의 FAIL은 유효 기록이며, 그것이 다른 원형까지 반증한 것은 아니라는 적용 범위만 보완한다.
C/D/HOLD를 자동 승격하지 않는다. 정식 B×B, host 연결, Core/Survivor의 기존 권한·sample 기준은 읽어서 적용한다. 상충하는 규정은 명시하고 영향을 받는 승격만 보류한다.
연구용 offline 부품 비교와 실제 host 교체/등급승격은 분리한다. 허용된 역할 비교에서는 standalone 수익성 대신 host-alone 대 host+component의 기여를 측정할 수 있지만, 그 결과만으로 운영 주입 권한을 만들지 않는다.

8. 같은 Work에서 실제 경제비교까지

전체 27항목은 감사 대상이며 27개 전부 새로 경제실행하라는 뜻이 아니다.
첫 경제 배치의 신규 identity와 FULL 실행 상한은 각각 6개다. 이것은 본 지시문의 작업 예산이지 SSOT 승격 임계치가 아니다.
새 대조군이 필요한 경우도 이 상한에 포함한다. 확정된 예산이 더 엄격하면 그것을 적용한다. 6개를 채우려고 후보를 만들지 않는다.

후보 선정은 결과를 보기 전에 원자료 대응, 실제 확인된 차이, 현재 데이터 가용성, 기존 실험과의 비중복성으로 결정한다. 재료군도 같은 기준으로 심사하고 incumbent만 우선해 다른 가능성을 봉쇄하지 않는다.
최소 한 후보에서 source-case-code 검수가 완료되면 같은 Work에서 구현·경제실행·검산으로 이어간다. 실제 source/권한 장애가 없다면 조사·문서만 만들고 종료하지 않는다.

실행 전 동결:
parent/child ID, source-rule mapping, 변경축, 코드 SHA, 데이터/비용/체결/구간 hash, 재현/이식 구분, 예산, 금지 반복, 소유자, 기대 검증 내용.
기존 exact parent의 원장·조건이 동일하면 저장값을 재사용한다. 동일성이 입증되지 않으면 다르다고 표시하고, 필요한 신규 matched control만 예산에 포함한다. 무조건 재실행 금지 때문에 비교 불가능한 표를 만드는 것도 금지다.

- 가능한 동일 6심볼, canonical 15m/30m, source gaps 보존, 동일 비용·점유·초기 자본 조건.
- 실측 12개월 원천부터 사용한다. 없는 24개월·체결·L2를 합성하지 않는다.
- 동일 사건 비교와 전체 시간순 재생을 함께 봐서 추가 점유가 뒤 거래를 막은 효과까지 포함한다.
- 하나의 규칙 변경인지 하나의 상태기계 복원인지 명시한다. 상호의존 규칙은 논리적 한 묶음으로 취급할 수 있으나 진입/청산/시간봉을 몰래 함께 바꾸지 않는다.
- 부품 조합은 필요한 경우 P / P+A / P+B / P+A+B를 모두 보고한다. 이미 완료된 PR1339의 같은 조합을 다시 돌리지 않는다.
- 15m 진입과 30m 문맥/청산은 사용 가능한 완료봉 시각과 실제 경과시간을 각각 기록한다.
- 검증된 resting order 엔진이 없으면 OHLC에서 유리한 선후 체결을 가정하지 않는다. 보수적 실행 모델의 한계를 표시한다.
- 과거에 관찰한 12개월/rolling은 개발·역사 진단이다. untouched OOS 또는 genuine fresh라고 부르지 않는다.
- 결과를 본 뒤 같은 holdout에 규칙을 다시 맞추지 않는다. 기존 실패한 4봉/BE/EMA-loss 등의 숫자만 바꿔 새 벤치마킹처럼 재개하지 않는다.
- 원문에 더 가까워졌다는 이유만으로 후보를 채택하지 않는다. 비용 후 성과·위험·표본·승리 보존을 별도로 판단한다.

9. 성과 보고 — 보기 좋은 숫자보다 기여 분해

원형/child마다:
TF·identity/SHA·실행조건, T·T/day, WR(%), gross/T·cost/T·net/T(bps/T), Net(bps), PF, 실현DD(bps), 최대연패, ES5와 손실 tail, 미완결, 보유시간 중앙값/p95(분), 비용1x/2x, 창별·월별·종목별 결과.
계좌곡선/MTM DD를 실제로 계산하지 않았다면 N/A. 연구 거래 명목 bps를 계좌 수익률로 바꾸지 않는다.

효과 분해:
기존 공통 거래 변화 / 누락 원형 / 추가 거래 / 기존 winner 이익 보존 / loser 손실 절감 / 점유·후속 거래 / 단일 큰 승리 제외 시 변화 / 동시 방향 손실 군집.
T·WR·Net·DD 동시 개선, 상충관계, 악화를 구분한다. 모든 지표 동시 개선만을 억지 PASS 목표로 삼거나 한 지표 개선을 전체 성공으로 부르지 않는다.
30m Squeeze의 과거 positive-window 3/9를 그대로 실패월6개로 읽지 않는다. 빈 구간과 음수 구간을 분리한다.
새 임의 PF/WR/gross-bps/sample/DD 수치를 승격 기준으로 만들지 않는다. 기존 SSOT에 없으면 미결속으로 표시하고 승격은 보류한다.

필수 최종 표:
A. 전체 감사표: 대상 / 역할 / source / 실제 실행본 / 이전 판정 범위 / 확인된 차이 또는 의도한 변형 / 수정 여부 / 검수 결과 / 다음 상태.
B. 신규 경제표: parent vs child의 T·WR·Net·Net/T·PF·DD·tail·cost2x·winner 보존·판정.
C. 탈락 재검토표: 유지한 FAIL / 원형까지 일반화 불가한 FAIL / 자료 부족 / 재료 역할 미평가 / 재검증 후 살아난 후보 수.
실제로 재검증하지 않은 것을 '살아났다'고 하지 않는다. Top7 교체·재료 승격은 실측 근거와 권한이 있는 경우에만 별도 보고한다.

10. 병렬 작업과 변경 마무리

- Orchestrator 한 명만 후보/경제실행/예산/최종 통합을 소유한다.
- 원자료 조사, 계보 추적, 원문 사례 작성, 구현, 반증 리뷰는 가능한 범위에서 subagent/worktree로 나눈다. 실제 사용 가능한 병렬 수만 보고한다.
- 같은 파일·후보·경제실행을 중복 소유하지 않는다. 각 단계의 산출물 경로와 SHA를 인수인계한다.
- 관련 unit/integration/causality 테스트, 저장 원장 독립 산술 검산, 기존 Black/Ruff/Mypy 및 적용 CI, 리뷰, 정상 PR/merge, 고정 merge 재검증까지 한다. 새 봉인 때문에 기존 frozen 파일을 다시 써서 맞추지 않는다.
- 검증 CI에서 완료 경제실험을 반복하지 않는다. 기존 호가/forward/paper 서비스를 무단 재시작·교체·중지하지 않는다.
- 유료 API·추가 인프라의 새 지출을 임의로 승인하지 않는다. 승인된 예산이 있으면 사용내역을 별도 기록한다.
- Work 세션의 종료와 서버 프로세스의 가동 상태를 구분한다. fresh 표본을 기다린다면 그때의 코드/규칙/경계/상태만 정확히 저장한다.
- 중단에 대비해 source mapping, 기대 사례, 후보 registry, 검수 결과, 진행상태, 재개 위치를 durable하게 저장한다.

종료 보고는 경제표와 확정된 원인부터 제시한다. '조사했다', '테스트가 많이 통과했다', 'PR을 병합했다'를 수익 개선과 혼동하지 않는다.
핵심 산출물은 검수된 실제 매매 규칙, 재현 가능한 수정본, 동일 조건 경제결과, 근거 있는 다음 선택이다.
