[Work 후속 실행문 초안 — G4 경제성 개선으로 목표 복귀]

repo=leegkssk2000-commits/vultr-z
proposed_scope_key=G4_SCALP7_MATERIAL20_ECONOMIC_DEVELOPMENT_AFTER_PR1340_V1

이 문서는 사용자가 Work에 전달할 후속 범위안이다. 작성만으로 Work가 실행되거나 기존 예산이 갱신된 것은 아니다.
아래 제안 배치를 실제 실행 지시로 전달하는 경우에만 해당 범위를 사용한다. 기존에 더 엄격한 후속 승인이 있으면 그것을 우선한다.
목표는 현재 사용자가 지정한 G4의 전략 경제성 개발이며, 이 문서로 공식 G 상태·승격·주문 권한을 변경하지 않는다.

0. 목적과 시작점
- 현재 15m/30m Scalp7 및 재료20에서 공개 자료·기존 코드·실험 결과를 재사용해 경제적으로 유지/개선/대체할 후보를 만든다.
- 원문 충실도 감사는 개발 전제이지 최종 성과가 아니다. 이번 주력은 비용 후 경제성 개선이다.
- PR #1340의 27개 감사와 5개 신규 실행/4개 비교는 완료된 선행 배치다. 그 배치의 완료를 G4 완료로 표시하지 않는다.
- 보존 기준 PR #1340 merge: 41535742994ee7d442375cc0d1b34325213f5736. 시작 시 최신 origin/master, Issue #1334 전체 후속 기록, open PR/worktree/예약을 확인해 이후 작업까지 보존한다.
- Work가 조사·후보선정·구현·경제실행·리뷰·통합의 단일 담당자다. Chat의 동일 후보 병행 경제실행을 가정하지 않는다.

기존 WORK_NEXT 및 SCALP7_CONNECTED_TOOLS_ADDENDUM_V2.txt의 데이터·출처·권한·중복 방지 규칙도 유지한다.
첨부 가능한 SCALP7_PR1340_SAVED_LEDGER_DIAGNOSIS_20260919.md는 읽기 전용 추가 집계다. 확정 원인이나 새로운 경제성과로 취급하지 않는다.

2. 확정 사실과 가설을 분리한다
- 이번 실패 HG/RSI/Break/SR child는 채택하지 않고 원형·원장·실패 판정을 보존한다. 같은 숫자만 바꿔 재시험하지 않는다.
- HG의 공통 완료 사건 92개는 순손익 변화가 없고, 거래 집합 교체에서 악화했다. 같은 시각의 child 신호 부재가 의도한 규칙인지 오류인지부터 구분한다. 과거에 돈 번 16건을 whitelist로 복원하지 않는다.
- SR 첫 완료봉 scratch 손실 집중은 기술통계다. scratch 제거가 수익 개선이라는 인과 증거가 아니다.
- Break 추가 경로의 stop 손실 집중은 진입 문맥과 stop 위치 중 어느 것이 잘못됐는지를 분리하지 못한다. 손절 사례만 삭제하지 않는다.
- 정확한 signal timestamp 기준 추가/누락은 동일 시장 기회의 시각 이동일 수도 있다. 독립 신규 기회로 자동 집계하지 않는다.
- 원문에 없는 규칙을 추측해 '정확 재현'이라고 하지 않는다. 의도한 adaptation과 구현 오류도 구분한다.

3. 경제개발의 세 경로 — 모든 이름을 억지로 살리지 않는다
A. 기존 양수 기준 강화
- Keltner/HG와 Squeeze의 동결 원형은 변경 없이 비교 기준으로 보존한다. 역사상 양수가 formal PASS라는 뜻은 아니다.
- 원형을 보존한다는 것은 모든 신규 후보가 원형의 진입·청산을 무조건 상속한다는 뜻이 아니다.
- 과거 손익을 보고 승리만 선택하지 말고, 원자료와 현재 관측 데이터로 설명할 수 있는 진입 지연/비중복 기회/실패 판단의 개선을 제안한다.
- Squeeze 완료30m 문맥→15m 실행은 미실행 여부와 실제 근거를 먼저 확인할 제안 중 하나다. 반드시 실시하거나 더 수익적이라고 가정하지 않는다.

B. 실패 전략의 경제적 재구성
- Rider/Break/Supertrend의 기존 음수 구현은 대조군·실패 증거로 남긴다. 구현 오류가 없다는 이유만으로 해당 계열의 경제개발을 종료하지 않는다.
- 공개된 매매 문맥→setup→trigger→초기 위험→전제 무효화→청산/보유시간을 서로 맞는 하나의 매매 구조로 연결한다.
- 기존 코드에서 재사용 가능한 부분을 회수한다. 완전한 새 구조가 필요하면 별도 후보로 선언하고 원형과 전체 시스템 성과를 비교한다.
- 이 경우 여러 구성요소가 함께 바뀐 효과를 단일 지표의 효과로 주장하지 않는다. 가능한 최소 제거 비교는 예산 안에서 수행한다.
- MR은 비용 민감도와 두 leg의 수렴/보유시간 정합성으로 심사한다. Micro는 실측 입력이 없으면 대체 자료를 꾸며내지 않는다.

C. 재료의 역할별 기여
- 진입 문맥/청산/위험관리 재료는 해당 역할에 맞는 offline P 대 P+component 비교 후보로 심사한다.
- 독립 진입 전략의 실패만으로 모든 부품 가치를 폐기하지 않는다. 반대로 부품이라는 이름만으로 경제검증을 면제하지 않는다.
- 단순 조합 수 증가나 임의 C×C 탐색은 금지한다. 특정 기존 전략의 확인된 문제와 출처가 있는 부품의 역할을 연결한다.
- 공식 B×B, 운영 host 주입, Core/Survivor 승격 권한은 기존 SSOT대로 유지한다. 충돌하는 정책을 연구라는 이름으로 우회하지 않는다.

4. 후보 선정 기준 — 수정하기 쉬운 것보다 경제적으로 시험할 이유
각 제안은 경제결과 전에 짧게 답한다.
(1) 어느 원자료의 어떤 조건/사례를 재사용하는가?
(2) 현재 전략의 어떤 손실 또는 누락 기회를 겨냥하는가? 무엇이 사실이고 무엇이 가설인가?
(3) 진입·위험거리·실패 판단·보유시간이 왜 함께 맞는가?
(4) 필요한 데이터가 실제로 있는가? 같은 조건 대조군을 확보할 수 있는가?
(5) 기존 실패와 무엇이 실질적으로 다른가? 반증되면 무엇을 중단하는가?
- 후보 선정 단계에서 미래 수익을 증명하라고 요구하지 않는다. 필요한 것은 사전 경제가설과 검증 가능성이다.
- 새로운 버그 발견 또는 원문과의 차이만으로 경제실행 우선권을 주지 않는다.
- 이름만 인용한 지표 조합 대신, 필요한 원문 문단·차트 사례와 코드 경로를 직접 연결한다.

5. 제안 후속 배치의 유한 예산
- 논리적으로 구분된 경제개선 가설 최대 3개.
- 신규 identity 최대 6개, 신규 FULL 경제실행 최대 6회. 새로운 matched control과 조합/제거 비교도 포함한다.
- 이는 후속 배치 제안 상한이다. PR #1340의 남은 예산을 자동 이월·재충전한 값이 아니다.
- 실제 선택은 근거 있는 후보만 한다. 개수를 채우기 위한 후보를 만들지 않는다.
- 기존 exact 동일조건 대조군 원장은 재사용한다. 비교조건이 달라 새 대조군이 필요하면 예산에 포함하고 실행한다.
- 경제 결과를 보는 probe/screen도 숨기지 않고 기록한다. 명칭을 바꿔 예산 밖 탐색을 늘리지 않는다.
- 각 비교의 논리가 서로 의존하면 한 구조로 사전 고정한다. 결과를 본 뒤 해석/규칙/구간을 바꾸지 않는다.
- 상한 도달 시 채택0이어도 결과는 정직하게 종료한다. 그때의 상태는 '이번 배치 종료·G4 개발 미완료'이지 G4 PASS가 아니다.

6. 실제 실행과 판단
- 현재 공식 데이터·비용·15m/30m 시각·source gaps·자본 및 점유 조건을 보존한다. 원형/child 차이를 사전 기록한다.
- 원문→명세→함수/코드 SHA→실제 호출 경로→사례 테스트를 결속한다. source/logic/economics/fresh를 분리한다.
- 현재 승인된 역사 구간에서 실제 전체 시간순 재생을 한다. 추가 포지션이 기존 승리를 막거나 후속 기회를 만드는 효과도 포함한다.
- 이미 본 12개월/rolling은 개발 진단이다. 새 independent/fresh 성과로 표시하지 않는다.
- 거래비용과 필요할 경우 계산/API 비용을 별도로 보고한다. 유료 API·인프라 추가 지출은 별도 명시 승인 없이는 하지 않는다.
- 긍정적인 MFE나 사후 회복을 곧바로 실현 가능한 이익으로 세지 않는다. 필요한 시각/체결 순서를 관측하지 못하면 한계를 기록한다.
- T·WR·Net·Net/T·PF·DD·연패·tail·winner 훼손·추가/누락/시각 이동·월/심볼 집중·비용1x/2x를 비교한다.
- T 증가만으로 개선이라 하지 않는다. T 감소만으로 자동 기각하지도 않는다. 수익/위험/기회 감소의 상충을 같이 보고 기존 SSOT로 판단한다.
- Net가 더 덜 음수가 됐다는 이유로 standalone Survivor라고 하지 않는다.
- 표본/승격 수치와 G 상태는 현재 SSOT를 읽어 적용한다. 새로운 고정 WR/PF/gross-bps 임계치를 만들지 않는다.

7. 범위 밖과 병목 분리
- 단순 LLM 직접매매, 숫자/이미지 입력 A/B, ML-Light, 별도 Bot/Skill/Method의 대규모 조합을 이번 G4 배치의 필수작업으로 끼워 넣지 않는다.
- 단일 전략의 경제평가에 필요한 진입/초기 위험/무효화/청산 명세는 G4에서도 정의한다. 이를 핑계로 별도 Method/Skill 최적화 전부를 앞당기지 않는다.
- 기존 forward/Paper/Micro의 관측 장애는 현재 상태를 읽어 확인하고 별도 운영 복구 항목으로 인계한다. 전략 개선을 서비스 복구 작업으로 대체하지 않는다.
- 서비스 재시작·새 fresh 경계·Paper/Live 승격은 이 경제개발 범위안만으로 승인하지 않는다. 기존 frozen 관측을 섞거나 되돌려 세지 않는다.

8. 완료 보고와 책임
- 첫 결과: 이번 후보를 경제적으로 시험한 이유, 재사용한 원자료/코드, 실제 parent→child 경제표, 실패/유지/추가검증 판정.
- 후보별 표에 '복원/강화/대체/역할 재사용/기각/미실행'을 보고용 분류로 남기되 runtime enum을 바꾸지 않는다.
- 기존 감사는 되풀이하지 말고 필요한 공백만 보완한다. 문서·테스트·PR 수는 수익개선 지표가 아니다.
- 관련 테스트·독립 검산·리뷰·CI·정상 PR/merge·고정 병합본 검증을 마무리한다. 완료 경제실험을 CI에서 재실행하지 않는다.
- 결정된 비교가 완료되면 결과를 저장·보고한다. 전체 후보 작업이 끝나야 첫 경제결과가 보이는 방식은 피한다.
- 주문·LIVE·공식 승격은 계속 BLOCKED. 별도 승인과 SSOT gate 없이는 열지 않는다.

한 문장 목표:
'감사를 다시 완료하는 것'이 아니라 '확인한 원자료와 기존 자산을 사용해 15m/30m에서 실제로 더 나은 경제후보를 만들고, 그 후보가 어디까지 검증됐는지 명확하게 판정하는 것'이다.
