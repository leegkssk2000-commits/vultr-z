## 3. 현재 개발에 붙일 지점 — 매매규칙 변경 아님

### H02 Keltner

`HGObserver`는 종목/연속 세그먼트별로 하나씩 유지한다. native `_hg_event`가 실제 호출되는 지점(i>=121)에서 `observed_hg_call(observer, state, row, previous)`를 사용하면 원형을 한 번 호출하고 raw `dataclasses.asdict` 전후 상태를 기록한다. **원형을 먼저 호출한 뒤 이 wrapper까지 중복 호출하면 안 된다.** 별도 observe 메서드를 쓸 때도 sanitized null state가 아니라 raw dataclass 전후 사본을 넘긴다.

확인할 값은 최초 touch 시각, weak-state 유지 여부/봉수, 다시 strong이 된 후 native event, 기존 승인/거절·거래 키다. 숫자 25/30은 현재 원형 조건의 관측일 뿐 새 튜닝 범위가 아니다. 이미 승인된 fresh-touch의 거절 후 reset과 그 이전 weak-state 보존은 분리한다. 무조건 weak 상태를 초기화하는 Child는 만들지 않는다.

이번에는 native component 동일성까지 시험했다. **전체 Keltner 실행기에 observer를 통합한 경제 재생은 미실행**이다. 기존 비교가 먼저 가능하면 이 선택 관측의 통합 완료를 기다리지 않는다.

### H01 Squeeze

`scan_saved_squeeze_paths(frames, saved_report)`는 기존 승인된 `scan_saved_trend_triggers`의 원천/57T 영수증 검사를 재사용한다. 전 거래의 원래 종료 이전 확정봉에서 native `_last_momenta`로 최초 음수전환, 신호봉저가 이탈을 관측하고 저장 손익과 별도 namespace로 연결한다. PANIC은 대조군이며 signal-low 정책 적용 대상은 TREND_DISPERSED뿐이다.

원래 stop·갭·원래 종료보다 빠른 관측인지, 관측 뒤 원래 승리로 회복했는지 양쪽을 남긴다. 당시 값과 사후 outcome을 합쳐 실행 feature로 쓰지 않는다. 입력 경로가 불완전하면 UNKNOWN/오류이며 ‘발동 0’이 아니다. 조기청산으로 피한 금액을 이 mapper에서 만들어내지 않는다. 실제 금액·후속 점유는 승인된 전체 시간순 비교에서만 계산한다.
