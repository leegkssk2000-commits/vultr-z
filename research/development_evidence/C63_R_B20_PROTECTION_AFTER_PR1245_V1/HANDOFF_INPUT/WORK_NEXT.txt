1. 이번 승인은 실행 승인이다
사용자는 직전 제안대로 진행하고 Chat와 Work의 역할을 나누라고 승인했다.
이 Work는 신규 후보 최대 1개·기존 두 기사용 구간 최초 FULL 평가 각 1회,
필요 최소 구현·테스트·관련 CI·PR·정상 병합·정확한 병합본 검증의 단일 담당자다.
진단 보고만 반복하고 다시 승인을 기다리지 말고, 승인된 수정의 실측까지 수행하라.
다만 실행에 필요한 실제 자료·권한·무결성이 없으면 정확한 막힘만 기록한다.
기존 PR1245의 REPORT_ONLY는 종료된 범위에만 적용한다. 이 후속 승인을 막지 마라.
동일 작업의 이미 실행된 결과·진행 중인 담당자가 있으면 회수/승계하고 중복 실행하지 마라.

2. 역할과 소유권
Chat: 공개 자료와 적용본 대조, 저장 원장 진단, 단일 수정 명세, 이후 결과의 별도 검토.
Work: 전체 저장소의 최소 코드 구현, 합성·통합 시험, 유일한 경제 실행/예산/브랜치 담당,
      실제 전후 경제표, 필요한 CI·리뷰·PR·병합·정확한 병합본 저장 검증.
다른 Chat/Work와 같은 시장자료를 중복 재생하지 않는다.
서브에이전트를 쓸 수 있으면 메인 실행 담당 외에 읽기 전용 구현/누수 검토자 최대 1명만 둔다.
별도 검토자는 시장 재생·외부 유료 API·동일 파일 쓰기 권한을 갖지 않는다.
기존 자동 리뷰가 역할을 충족하면 검토자를 추가하지 않는다.

정확한 추가 규칙:
- held=20인 완료봉에서 기존 R 청산 사유가 없고 실제 연장 상태가 유지될 때만
  B=해당 봉의 종가를 1회 저장한다.
- held>=21인 완료봉에서 기존 R 청산 사유가 없고 close<B이면 추가 청산 신호를 낸다.
- 실제 체결은 기존 엔진의 다음 관측 가능한 봉 시가 의미를 그대로 사용한다.
- close==B는 발동하지 않는다. B를 갱신하거나 같은 봉에서 과거에 적용하지 않는다.
- 기존 R 청산이 먼저/동시에 발생하면 기존 사유가 우선이며 추가 조기 개입으로 세지 않는다.
- B가격이나 신호봉 종가에 체결했다고 계산하지 않는다. 갭은 실제 다음 시가에 반영한다.
- 다음 체결봉이 없으면 기존 pending/open/censor 처리대로 남긴다. 가상 체결을 만들지 않는다.
- B>entry, C20>C19, 추가 일봉 방향 조건, 이익목표, 부분익절, 수량 증가는 넣지 않는다.
- 연장 재승인·재무장·시계 리셋·연도/종목/거래ID/최종승패 예외를 만들지 않는다.
- 필요한 원천이 결측/불량이면 명시적 무결성 실패이며 값을 추정하지 않는다.

주의: 동일한 원래 진입 포지션의 held20까지 행동을 보존한다는 뜻이다.
이후 조기 청산으로 후속 진입 기회가 바뀌면 이를 전부 FULL에 포함해야 한다.
결과를 원래 거래 목록에 강제로 맞추거나 실제 체결 전에 점유를 해제하지 않는다.

10. 저장·검증·종료
원본/실패/원장/규칙/코드/입력 해시·예산·영수증을 영구 보존한다.
PR/master CI는 저장 해시·회계 검산·합성 회귀만 수행하고 전략 경제를 반복 실행하지 않는다.
최종 리뷰 전에 이번 경제 dispatcher와 쓰기 인증 경로를 제거한다.
필요 CI·리뷰·정상 PR 병합 후 정확한 merge SHA에 대한 저장 검증까지 한 번 완료한다.
별도 수집 커밋으로 master가 바뀌어도 그 HEAD를 쫓아 완료 검사를 반복하지 않는다.
REJECT/TRADEOFF라도 승인 범위가 끝났으면 이번 Work만 REPORT_ONLY로 닫고 최종 보고 후 종료한다.
막히면 실제 command/run ID·마지막 의미 있는 상태·저장 위치·미완료 항목을 남겨 CHECKPOINTED/BLOCKED로 보고한다.
자동 다음 후보·유료 API·실주문·배포·G5B 교체는 없다. 기존 관측기는 중지하지 않는다.
