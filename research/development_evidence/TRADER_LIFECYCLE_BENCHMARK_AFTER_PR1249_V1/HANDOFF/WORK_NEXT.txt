4. 이번 구현에서 반드시 달라지는 것
C63는 원형 대조군으로 그대로 둔다. 새 후보는 기존 C63의 신호 목록에 추가 필터만 붙이지 않고, 원문 준비 조건부터 독립된 시간순 신호를 생성하는 연구 가지다. 공용 데이터·비용·점유·원장·조건부 주문 프리미티브는 재사용한다. 새 범용 백테스터는 만들지 않는다.
원문상의 일봉·3거래일·3일 추적을 4시간봉3개 또는 보유20개로 바꾸지 않는다. 4h 입력6개로 완성 UTC 일봉을 만들고 준비/관리 관측과 주문 유효시각을 기록한다.
상승 추세의 압축과 컵/핸들 준비 -> 나눠 준비한 눌림/재돌파 주문 -> 최초 위험 제한 -> 진행 실패 점검 -> 익절1/익절2와 보호 상향 -> 잔량 추적/최종목표 -> 종료/새 준비 순서다. 원래 R40/B20/F/time20 규칙은 새 후보에서 켜지 않는다.
분할 진입은 원래 단일 고정 기준명목 내 배분일 뿐 노출 확대가 아니다. 총 배정1.0 초과, 무제한 DCA, 손절 하향/위험 확대는 금지한다. Carter의 계좌5% 위험은 실계좌와 연구 계좌에 복사하지 않는다. 동일 명목 결과와 최초 위험거리·노출을 따로 보고해 리스크를 더 쓴 이득인지 확인한다.
단계별 정확한 기계화는 CARTER_CRYPTO_ADAPTATION.json A01~A12를 따른다. 전략 의미 변경이 꼭 필요하면 첫 성과 전만 허용하고 원문/구현선택/사유를 남긴다. 숫자를 여러 개 돌려 가장 좋은 것을 고르는 것은 금지한다.

6. 원문 생명주기·인과 검증 후 사전 동결
ACCEPTANCE_TESTS.json의 사례는 요구사항이며 이미 통과한 시험이 아니다. Work가 실제 코드에 실행한다.
공개 원문 각 단계 -> 상태/코드 위치 -> 사용 가능한 관측값 -> 주문 시각/가격 -> 비용원장 -> 결과를 연결한 SOURCE_TO_EXECUTION_MAP을 작성한다. 각 행은 SOURCE / IMPLEMENTATION_CHOICE / UNSUPPORTED 중 하나로 구분한다.
사례 chart 리뷰는 준비와 실패 맥락을 확인하는 용도다. 이미지의 고가/저가를 정밀 OHLC로 추측하거나 source 사용자가 실제 체결했다고 기록하지 않는다. 실제 역사 거래 replay와 인공 상태기계 시험을 섞지 않는다.
코드·원천·비용·입력·명세·승격기준을 첫 경제 결과 전에 고정한다. 각 FULL은 실행 전 영구 예약/시작 기록을 원격에서 읽어 확인한다. 결과 뒤 임계치·출처·기간·종목·쿼리 기준은 수정하지 않는다.

7. 경제 평가와 채택을 구분한다
C63 대비 후보의 완결/미완결, 승률, 평균승/패, 실현손익비, PF, 종료 net, 비용x2, DD, 최장연패, 최악/하위10%손실, 노출, 월/종목 집중, 최초 위험거리, 부분체결 비용을 비교한다. 비용x2는 모델 스트레스이지 실비다. 매매 한 campaign의 부분 leg를 별도 승리로 세지 않는다.
기존 m1_er14_study_v1.checks 8개 WR/net/cost2/DD 판정을 보존한다. 원문 재현 충실도와 경제 기준은 별도다. 공개 매매방법은 특정 지표만 조금 고친 ablation이 아니므로 전체 패키지 효과라고 보고하며 특정 구성요소의 독립 효과가 입증됐다고 하지 않는다.
새 준비·진입 때문에 trade identity가 달라진다. 정확히 공통인 거래, 대조군에서 제외, 새 거래, 미완결 전환을 보존하고 완전한 집계가 전체 증분과 일치하도록 한다. 날짜가 겹친다고 같은 거래로 강제 대응하지 않는다. 시간/종목/동일 episode의 분석용 대응은 비인과적이라는 표기를 유지한다. 기존 일반승리·대승의 커버리지/이익 포기를 별도 산출하고, 대응 불가 거래를 지우지 않는다.
두 창의 산술 요약과 각각의 약점을 나란히 보고한다. DD를 합치거나 연속계좌 성적·독립 OOS·G5 PASS라고 하지 않는다. 수익이 높아져도 위험이 커지면 TRADEOFF가 남는다. 검증된 개선이면 그 후보를 다음 개발 자산으로 보존하지만 자동 운영교체하지 않는다.
