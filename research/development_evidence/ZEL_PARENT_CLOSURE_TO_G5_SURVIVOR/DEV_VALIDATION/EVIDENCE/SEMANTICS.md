# KR3 native DEV evidence scope

The native signal/exit code is unchanged. The new adapter decodes only the original 2,250-row DEV2025 prefix per frozen symbol through 2025-12-29T08:00:00Z. It reuses the old prefix reader after opaque checksums against the original canonical manifest. It does not run a strategy or decode the validation/OOS suffix.

## P2 numeric provenance

The inventory includes all numeric Python literals and executable formula literals in the six native KR3/M2/KR1/D/N/reference modules, bounded EMA DSL and feature builder, shared geometry, charge wrappers, funding boundary counter, proxy cost owner, and open-mark adapter. Whole-file enumeration is deliberately a conservative superset, not a claim that every infrastructure literal is a tunable strategy parameter. Cost snapshot numbers and stored evaluation constants remain attached separately.

The inherited values and their byte owners are now inspectable. This does not manufacture development justification: pure design priors retain null justification and selection from reused DEV is explicit. The unchanged P2 owner may therefore still fail after inventory coverage is fixed.

## P3 first semantic mismatch

`a1_alpha_proof_gate_v1.evaluate_p3` requires numeric medians but does not itself define their path horizon. Its existing producer `a1_gen2_alpha_proof_e2e_v1._simulate/_p3` uses the fixed `max_hold_bars` horizon from each entry. Its MAE is a nonnegative loss magnitude.

The stored native KR3 FULL trade rows instead contain excursions over their actual variable holding interval. Their MAE is nonpositive; a next-open exit includes only that open, not the remainder of its candle. Converting the sign alone does not make the horizon identical. The new adapter reports median held MFE, signed MAE, MAE magnitude and variable-horizon gross move from closed rows; it retains the open count separately. It does not rename variable-horizon gross return as fixed-horizon forward movement or put held-path medians into a differently defined formal field.

A KR3-specific P3 horizon/population mapping and registered launch owner remain necessary. There is no new sample threshold or JSON `true` launch assertion.

## P6 actual linkage and limits

`load_dev_slice` returns the verified prefix, historic policy, research cost bindings and a lineage receipt. The actual digest of the per-symbol decoded prefixes is recorded separately from the historic combined-dataset label; the latter is not represented as the hash of the 4h prefix alone. Original warmup/eligibility is preserved: no rows before the original calendar, index 239 is the first eligible signal index, and each EMA uses the original bounded `4*n` window and first-value seed.

Source-byte verification can establish immutable historical input. It cannot establish a retrospectively preregistered KR3 split. The same fixed snapshot spread/impact and P95 absolute funding reserve remain declared research proxies. Current BBO is not used as a historical fill. The unchanged P6 owner retains the split/proxy/verified-cost blockers.
